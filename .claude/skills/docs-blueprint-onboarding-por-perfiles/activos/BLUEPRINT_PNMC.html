2 · Qué es la plataforma (en lenguaje simple)

El Entorno Virtual del PNMC es la plataforma digital del Plan Nacional de Música para la Convivencia. Su propósito es cartografiar y fortalecer el ecosistema musical de Colombia:

Visibilizar

Un mapa interactivo de todo el país muestra escuelas de música, festivales, lutieres (constructores de instrumentos) y redes de investigación, municipio por municipio.

Co-gestionar

Las entidades aliadas (secretarías de cultura, universidades, redes de escuelas) administran la información de su propia red con cuentas y permisos delimitados.

Participar

Cualquier gestor cultural o ciudadano puede registrar su proceso musical, reclamar registros históricos que le pertenecen y mantener su información actualizada.

Toda la información pasa por un flujo de revisión del Ministerio antes de publicarse, con trazabilidad completa de quién hizo qué y cuándo (auditoría inmutable), y protección de datos personales según la Ley 1581 de 2012.

3 · Módulos y roles

Módulos del portal público

MóduloQué ofrece
Inicio + CMSPágina principal con textos editables desde la consola (sin tocar código), carrusel de las 8 estrategias territoriales del Plan.
Mapa ecosistémicoGeovisor con 3 vistas: marcadores agrupados por tipo, mapa de calor de densidad musical y coropletas por departamento. Filtros por departamento/municipio (estándar DIVIPOLA del DANE).
AgendaCalendario nacional de festivales y eventos, con filtros y geolocalización directa en el mapa.
NoticiasComunicados y crónicas con contenido enriquecido renderizado de forma segura.
EditorialBiblioteca digital: libros, metodologías y partituras del Ministerio con buscador y filtros.
GaleríaÁlbumes fotográficos de los encuentros territoriales.
ParticipaciónRegistro ciudadano con asistente de 3 pasos y motor de reclamación: el sistema cruza el municipio del usuario con los registros históricos "huérfanos" para que reclame los suyos en vez de duplicarlos.

Los 6 roles (control de acceso RBAC)

RolConsolaQué puede hacer
Webmaster/adminAdministración total: usuarios, textos del CMS, catálogos, auditoría, importaciones.
Gestor interno/adminModeración del Ministerio: aprueba/rechaza registros, solicita ajustes campo por campo, controla duplicados y calidad.
Aliado administrador/colaboradoresLidera una entidad aliada: KPIs de su red, gestiona su equipo, exporta datos de su red.
Aliado editor/colaboradoresCrea y edita registros de su entidad y los envía a revisión.
Aliado lector/colaboradoresSolo lectura de los registros de su entidad.
Colaborador externo/colaboradoresCiudadano/gestor independiente: registra y reclama sus propios procesos culturales.

Regla de oro: los aliados solo ven y tocan lo de su propia entidad; los datos de contacto personales se enmascaran en todo lo público (Habeas Data, Ley 1581 de 2012).

El flujo editorial (corazón de la gobernanza)

borrador→ en_revision→ ajustes_solicitados↔ aprobado→ publicado | rechazado | archivado

Cada transición queda grabada en una bitácora inmutable (quién, cuándo, estado anterior y nuevo, observaciones) que ningún usuario puede modificar ni borrar.

4 · Arquitectura técnica

Monorepo con tres piezas + documentación. Arquitectura N capas orientada al dominio, con los límites internos ya definidos para una evolución futura a servicios independientes. Detalle completo con diagramas: ARQUITECTURA_PNMC.html

PiezaTecnologíaQué contiene
pnmc-web/React 19 · Vite · Tailwind CSS · LeafletPortal público, geovisor y consolas. ~26.000 líneas organizadas por dominios funcionales con carga diferida por ruta.
pnmc-api/C# · .NET (Minimal APIs) · EF Core4 proyectos: Api (16 módulos de endpoints bajo /api/v1), Contracts (DTOs), Domain (36 entidades), Infrastructure (acceso a datos, seguridad, auditoría). Autenticación por cookie, rate limiting, middlewares de seguridad.
pnmc-database/SQL Server (T-SQL)16 scripts versionados e idempotentes: 9 de esquema + 7 de semillas (catálogos, DIVIPOLA completo, datos de prueba) + procedimiento de métricas del mapa.
docs/MarkdownManual maestro + 11 sub-documentos (técnico, funcional, gobernanza, backlog). Ver mapa documental.

Cómo fluye una petición

Navegador → Frontend (React) → API REST /api/v1
   → Middlewares (contexto → cabeceras de seguridad → errores → CORS → rate limit → autenticación → autorización)
   → Módulo del dominio (ej. Gobernanza) → EF Core → SQL Server
   → DTO de respuesta → Frontend renderiza

Los 16 módulos del API por dominio

Catálogo (festivales, escuelas, lutieres, organizaciones, espacios, DIVIPOLA) · Mapa (TopoJSON + resúmenes) · Agenda · Noticias · Editorial · Galería · Participación · Autenticación administrativa · Autenticación externa · Gobernanza de registros (estados, reclamaciones, duplicados) · Aliados (administración + portal) · Entidades · Datos administrativos (importaciones, monitor) · Notificaciones · Compatibilidad legada.

5 · Despliegue local — paso a paso verificado

Esta es la ruta probada en Windows. Una persona nueva puede tener la plataforma corriendo en ~30 minutos.

0

Prerrequisitos

• Node.js 18+ · SDK de .NET 10 · SQL Server LocalDB (o SQL Server/Express) · sqlcmd · Git

Instalables con: winget install OpenJS.NodeJS.LTS Microsoft.DotNet.SDK.10 Microsoft.Sqlcmd

1

Clonar el repositorio

git clone https://github.com/edder-jimenez/Entorno_Virtual_PNMC.git
2

Crear y sembrar la base de datos

Iniciar LocalDB y crear la base PNMC_LOCAL; luego ejecutar los 16 scripts en orden (9 de pnmc-database/schema/ + 7 de pnmc-database/seed/, orden alfabético por versión) y al final EXEC dbo.sp_ActualizarMetricasMapa;

NotaEn SQL Server 2016, el script V20260525_02 puede fallar en un renombrado de columna bloqueado por una restricción CHECK sobre RolEnEntidad: se elimina la restricción, se renombra a RolAliado y se re-ejecuta el script (es idempotente).

3

Arrancar el API conectado a la base

$env:ASPNETCORE_ENVIRONMENT = 'Local'
$env:ASPNETCORE_URLS = 'http://localhost:8080'
$env:AZURE_SQL_CONNECTION_STRING = 'Server=(localdb)\MSSQLLocalDB;Initial Catalog=PNMC_LOCAL;Integrated Security=True;Encrypt=False;TrustServerCertificate=True;'
$env:Database__SeedBootstrapUsers = 'true'   # crea las cuentas admin y gestor al arrancar
cd Entorno_Virtual_PNMC/pnmc-api
dotnet run --project src/PNMC.Api --no-launch-profile

NotaLas cuentas de aliados y colaborador externo (usuarios 4–7) no las crea ningún script: se insertan en la tabla Usuarios reutilizando el hash de contraseña del admin, y después se re-ejecuta el seed 07 (datos de moderación), que las referencia.

4

Arrancar el frontend

cd Entorno_Virtual_PNMC/pnmc-web
npm install
npm run dev

El archivo pnmc-web/.env debe tener VITE_API_BASE_URL= (vacío) para que las llamadas pasen por el proxy de Vite — así funciona en cualquier puerto sin problemas de CORS.

5

Verificar

QuéURL

Consola administrativahttp://localhost:5175/admin

7 · Plan de trabajo — resumen ejecutivo

14–16 semanas de ejecución en 6 fases. Detalle completo: plan extendido · versión presentación.

F0 · Gobernanza y formalización1–2Radicación del proyecto ante el Ministerio (F-GSI-007), viabilidad, líderes designados, mesa de homologación tecnológica (GO/NO-GO #1), decisión de infraestructura.

F6 · Calidad y producción12–16Accesibilidad AA evidenciada, pruebas de carga, ethical hacking aprobado, capacitación, go-live como cambio formal (GO/NO-GO #2) y entrega documental completa.

8 · Marco normativo — la directriz del proyecto

Todo el trabajo se rige por 6 políticas del Ministerio convertidas en 63 ítems de cumplimiento verificables, revisados en cada hito. Lo esencial:

Formalización (P-GSI-003)

El proyecto se radica con formato F-GSI-007, el comité técnico da la viabilidad, se designan líder funcional y técnico, y el código resultante es propiedad del Ministerio.

Recepción técnica (DI-GSI-010)

Inicio de sesión institucional, auditoría con IP y firma de eventos, ethical hacking obligatorio, alta disponibilidad, paquete documental completo de entrega.

Desarrollo seguro (M-GSI-002)

Metodología SDL + OWASP Top 10, política estricta de contraseñas y sesiones, estándares de código. La arquitectura en capas del sistema cumple lo exigido.

Gestión de cambios (P-GSI-004 / M-GSI-003)

Todo paso a producción es un cambio formal con plan de reversa, aprobado por el comité semanal. Congelamiento de cambios del 15 de diciembre al 15 de enero.

⚠️ Decisión crítica pendiente

El manual de arquitectura (2021) referencia tecnologías hoy fuera de soporte. Se requiere acta de homologación tecnológica de la OTI que reconozca la pila moderna como cumplimiento equivalente — es el primer GO/NO-GO del plan. Detalle: conflictos abiertos.

Pendiente documental

Del Manual de Seguridad (M-GSI-005) solo se tiene la carátula: hay que solicitar el cuerpo completo a la OTI para cerrar la alineación de seguridad.

10 · Glosario para no desarrolladores

Frontend
La parte visual de la plataforma: lo que ves y tocas en el navegador.
Backend / API
El "motor" invisible: recibe las peticiones del frontend, aplica las reglas de negocio y consulta la base de datos. API es la puerta de entrada formal a ese motor.
Base de datos / SQL Server
Donde vive toda la información (registros, usuarios, textos). SQL Server es el producto de base de datos que usa la plataforma.
Semillas (seeds)
Scripts que llenan la base de datos con información inicial: catálogos, municipios y datos de prueba.
DIVIPOLA
La codificación oficial del DANE para departamentos y municipios de Colombia. Garantiza que "Bogotá" sea siempre el código 11001, sin errores de escritura.
RBAC (roles y permisos)
Sistema que decide qué puede hacer cada usuario según su rol (los 6 de la sección 3).
Flujo editorial
El camino que recorre un registro desde que alguien lo crea (borrador) hasta que el Ministerio lo publica, con revisión y trazabilidad.
Registro huérfano
Información histórica de censos anteriores que está en el mapa pero no tiene un responsable que la actualice; los colaboradores pueden "reclamarla".
CMS
Editor que permite cambiar los textos del portal desde la consola administrativa, sin programar.
Auditoría inmutable
Bitácora que registra cada acción importante y que no se puede alterar — exigencia para entidades públicas.
Despliegue
El proceso de instalar y dejar funcionando la plataforma en un computador o servidor.
Go-live
El día en que la plataforma sale a producción para el público real.
Ethical hacking
Prueba de seguridad donde especialistas intentan vulnerar el sistema de forma controlada para encontrar y corregir fallas antes que un atacante real.
OTI / GGSTI
Oficina de Tecnologías de la Información del Ministerio — el equipo técnico que guía, aprueba y recibe la plataforma.
